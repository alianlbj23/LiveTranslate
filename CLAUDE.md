# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

LiveTranslate is a real-time audio translation system for video players on Windows. It captures system audio via WASAPI loopback, runs speech recognition, and translates via LLM APIs, displaying results in a transparent overlay.

**Current phase**: Phase 0 Python prototype (Phase 1 will be a C++ DirectShow Audio Tap Filter).

## Running

```bash
# Must use the project venv (system Python lacks dependencies)
.venv/Scripts/python.exe main.py
```

Linter: `ruff` (installed globally). Run `python -m ruff check --select F,E,W --ignore E501,E402 *.py` to lint. E402 is intentionally ignored because `main.py` requires torch before PyQt6.

Install scripts (`install.ps1`, `update.bat`, and the portable `bootstrap.ps1` generated by `build_release.ps1`) keep every download off the system drive: pip/uv caches, uv-managed Python, and temp files all live under the project/app folder, and caches are deleted after a successful install.

## Architecture

The pipeline runs in a background thread: **Audio Capture (32ms chunks) -> VAD -> ASR -> Translation (async) -> Overlay**

```
main.py (LiveTranslateApp)
  |-- model_manager.py     Centralized model detection, download, cache utils
  |-- audio_capture.py     WASAPI loopback via pyaudiowpatch, auto-reconnects on device change
  |-- vad_processor.py     Silero VAD / energy-based / disabled modes, progressive silence + backtrack split
  |-- asr_client.py        Main-process ASR worker manager (spawn, Pipe IPC, timeouts)
  |-- asr_worker.py        ASR subprocess entrypoint; loads and owns one backend/model
  |-- asr_engine.py        faster-whisper (Whisper) backend
  |-- asr_funasr.py        Unified FunASR engine, dispatches to model-family adapters
  |-- asr_sensevoice.py    FunASR SenseVoice backend (better for Japanese)
  |-- asr_funasr_nano.py   FunASR Nano backend
  |-- asr_anime_whisper.py Anime-Whisper backend (litagin/anime-whisper, ja anime/galgame)
  |-- translator.py        OpenAI-compatible API client, streaming, JSON schema, context history
  |-- subtitle_overlay.py  PyQt6 transparent overlay (2-row header: controls + model/lang combos)
  |-- subtitle_window.py   Standalone subtitle window for OBS capture (outlined text, animations)
  |-- subtitle_settings.py Subtitle window settings UI (grid layout, text line editor)
  |-- control_panel.py     Settings UI (7 tabs: VAD/ASR, Translation, Style, Subtitle, Benchmark, Cache, Changelog)
  |-- dialogs.py           Setup wizard, model download/load dialogs, ModelEditDialog
  |-- benchmark.py         Translation benchmark (BENCH_SENTENCES, run_benchmark())
  |-- log_window.py        Real-time log viewer
```

### Threading / Process Model

- **Main thread**: Qt event loop (all UI)
- **Capture thread**: `_capture_loop` in `LiveTranslateApp` reads audio and runs VAD
- **ASR queue thread**: `_asr_loop` drains VAD segments and calls `ASRClient.transcribe()`
- **ASR worker process**: `asr_worker.py` owns the concrete ASR backend/model and runs inference over `multiprocessing.Pipe`
- **ASR loading**: `_switch_asr_engine()` stops the current worker, then starts the target worker in a background thread; if target loading fails, it restarts the previous worker from its saved config
- Cross-thread UI updates use **Qt signals** (e.g., `add_message_signal`, `update_translation_signal`)
- ASR readiness tracked by `_asr_ready` flag; pipeline drops segments while no ready worker exists

### Configuration

- `config.yaml` - Base configuration (audio, ASR, translation, subtitle defaults)
- `user_settings.json` - Runtime settings persisted by control panel (models, VAD params, ASR engine choice, optional `cache_path`). Takes priority over config.yaml on load.

### Model Config

Each model in `user_settings.json` has: `name`, `api_base`, `api_key`, `model`, `proxy` ("none"/"system"/custom URL), and optional per-model flags:

- `no_system_role` (bool): Merges system prompt into user message for APIs that reject system role (e.g. Qwen-MT)
- `thinking_style` (str, default "auto"): How to disable reasoning for thinking models — providers use incompatible request shapes (issue #38). Values: `auto` (heuristic: DeepSeek/GLM/Volcano Ark/Zhipu endpoints → nested style; official OpenAI/xAI/Anthropic endpoints → send nothing, they reject unknown params; otherwise Qwen style), `deepseek` (`{"thinking": {"type": "disabled"}}`), `qwen` (`{"enable_thinking": false}`), `vllm` (`{"chat_template_kwargs": {"enable_thinking": false}}`), `openai` (`{"reasoning_effort": "none"}`), `off` (send nothing — non-thinking models, LM Studio, Ollama /v1). Legacy `no_think: false` migrates to `off`; `translator.resolve_thinking_style()`/`thinking_disable_body()` are the single source of truth. An empty completion with completion_tokens > 0 logs a "thinking burned the budget" warning
- `prompt_style` (str, optional): `"sakura"` uses the SakuraLLM prompt format (fixed Simplified-Chinese system prompt, user message with 历史翻译 / 术语表 / input; `translator.SAKURA_*`), only when the target is Chinese. ModelEditDialog keeps fields it does not edit (`_EDITED_KEYS`)
- Local models: `local_models.json` is the catalog (shared with `launcher/gui.ps1`); `launcher/set_api_base.py` → `local_models.sync_local_models()` keeps one entry per installed catalog model (installed list from Ollama `/api/tags`; unknown list = remove nothing) and activates the selected one. `_on_model_changed` calls `local_models.remember_selected()` (writes `launcher/selected_model.txt`) and warms a local model in the background; the launcher sets `OLLAMA_MAX_LOADED_MODELS=1`
- Hardware advice: `hardware_profile.py` (stdlib + system_stats / model_manager / local_models) judges whether the speech model in use (`current_asr()`, GPU GB in `ASR_VRAM_GB`) plus each catalog translation model (`vram_gb`, quality `rank` in `local_models.json`, both from the 2026-10-20 benchmark) fits the card's **total** memory with `RESERVE_GB` 1.5 for the desktop: ok / tight (< 1 GB spare) / too_big. `launcher/hardware_advice.py` (JSON CLI: launcher / install / startup) feeds `launcher/gui.ps1` (row tags 【推薦】【接近上限】【顯示卡可能不夠】, a confirm before switching to a too_big model, the `lblHardware` line), the text menu, `setup.ps1` (fresh install picks `install_choice()`: Whisper turbo or SenseVoice + the best model that fits, writes it to `selected_model.txt`) and `start_jp_subtitles.ps1` (free-memory check for the pair in use, `vram.ps1`). When the helper fails, the launcher works as before without advice
- `streaming` (bool, default True): Per-model streaming toggle; streaming mode yields partial text via `translate_iter()` generator
- `json_response` (bool, default False): Uses `response_format={"type": "json_schema"}` with schema `{"t": "string"}` for structured output; mutually exclusive with streaming UI display
- `context_turns` (int, default 0): Number of recent (source, translation) pairs to include as multi-turn context in messages
- `input_price`/`output_price` (float, per 1M tokens): Token pricing for cost estimation displayed in MonitorBar
- `overrides` (dict, optional): Per-request OpenAI chat-completion params that override defaults — supported keys `temperature`, `top_p`, `max_tokens`, `frequency_penalty`, `presence_penalty`, `seed`. Only keys present in the dict are sent; absent keys fall back to constructor defaults (temperature/max_tokens) or are omitted entirely (others)
- `extra_body` (dict, optional): Provider-specific params (e.g. `thinking`, `thinking_budget`, `reasoning_effort`) merged into the request's `extra_body`. Explicit values override the automatic `no_think` parameter
- Proxy handling: `proxy="none"` uses `httpx.Client(trust_env=False)` to bypass system proxy; `proxy="system"` uses default httpx behavior (env vars)
- `Translator._build_request_kwargs()` is the single assembly point — it injects `overrides`, merges `extra_body` with `no_think`, and stamps `response_format` for `json_response`. All three code paths (`_translate_sync`, `_translate_streaming`, streaming `translate_iter`) go through it
- ModelEditDialog "Advanced Parameters" group uses `[Override] checkbox + value widget` pattern — unchecked rows don't write to the `overrides` dict, preserving backward-compat. `extra_body` is a multi-line JSON text field validated on OK
- Editing the active model in ModelEditDialog triggers `model_changed` signal to immediately apply changes

### Subtitle Window (subtitle_window.py)

Standalone transparent window for OBS capture, separate from the main overlay:
- `SubtitleWindow`: Frameless, transparent, middle-click draggable, auto-hides after timeout, default position (100, 100)
- `_SubtitleTextWidget`: QPainterPath-based outlined text rendering per line, with automatic word-wrap and entry/exit animations
- Text rendered to cached QPixmap; animations only blit the cached image (no per-frame path rendering)
- Each line has independent font, color, outline, alignment, animation settings
- Long text auto-wraps at punctuation/word boundaries, expanding widget height for multiple lines
- `desired_height()` returns height based on wrapped line count (never 0), preventing window collapse when empty
- Top / bottom edges (and the bottom-right corner) can be dragged to set a box height (`subtitle_mode.window_height`, 0 = fit to text, saved by main's `_save_subwin_state`). The box never clips text; text stays vertically centred in a taller box
- Window height animates smoothly (150ms OutCubic) when wrap count changes, keeping vertical center stable
- Animation order: exit animation → height change → entry animation
- Settings UI in `subtitle_settings.py`: grid layout, text lines as list with double-click edit dialog

### Overlay UI (subtitle_overlay.py)

The window is a rounded (12 px), ~85 % opaque dark card with a soft shadow painted in `SubtitleOverlay.paintEvent` (transparent `_SHADOW` margin around `#overlayCard`). Card / header style sheets are scoped by object name (`#overlayCard`, `#overlayHeader`) so they do not cascade into the Fluent widgets inside.

DragHandle is a 2-row header bar built from PyQt6-Fluent-Widgets (icon-only buttons, tooltips via `ToolTipFilter`):
- **Row 1**: Draggable title + `TransparentToolButton` icons (Subtitle toggle + ▾ options menu, Run/Pause, Clear, Full/Compact, Settings, Minimize, Quit). There is no hide button; the tray menu shows / hides the window. The overlay is a normal window (type Window, not Tool) so it always has a taskbar button; there is no Taskbar toggle (removed on request 2026-10-21). `WindowMinimizeButtonHint` is required or Windows does not iconify the frameless window. Minimize (`minimize_to_taskbar()`) iconifies to the taskbar with the system animation: `_add_window_animation()` adds WS_CAPTION / WS_SYSMENU / WS_MINIMIZEBOX natively on every `showEvent` (Qt resets the style when flags change, e.g. the top-most toggle) and `nativeEvent` answers WM_NCCALCSIZE so the caption takes no room (never call `super().nativeEvent` there: PyQt6 crashes). Painting stops while minimized (`setUpdatesEnabled(False)`, also when minimized from the taskbar): any repaint of this layered (translucent) window draws it back at its old place although Windows reports it iconic; check minimize on screen, not only `IsIconic`. A left click on the tray icon calls `toggle_from_tray()` (a second click within the double-click interval is ignored); the tray menu shows the window through `restore_window()`
- The frameless window is stretched up / down with `_EdgeResizeHandle` strips along the card's top and bottom edges (native `startSystemResize`, manual fallback)
- **Row 2**: `TransparentToggleToolButton` toggles (Click-through, Top-most, Auto-scroll; attribute names `_ct_check`/`_topmost_check`/`_auto_scroll` are used by main.py's tray sync) + Fluent `ComboBox` for model / source / target language (items carry the language code as `userData`)

MonitorBar (MIC/RMS/VAD bars, ASR device, CPU/RAM/GPU, ASR/TL counts, tokens and cost; CPU = whole machine, RAM = app process tree incl. the ASR worker, GPU = whole-card memory/load from NVIDIA NVML via ctypes in `system_stats.py`) sits in `_StatusSection`, a collapsible "狀態" block that is collapsed by default and hidden in compact mode.

Style system:
- `DEFAULT_STYLE` and `STYLE_PRESETS` defined in `subtitle_overlay.py` — 14 presets including terminal themes (Dracula, Nord, Monokai, Solarized, Gruvbox, Tokyo Night, Catppuccin, One Dark, Everforest, Kanagawa)
- Default style is a translucent dark card (`#16161d` at 85 %, 12 px radius); original text small grey, translation 15pt white semi-bold, timestamps / ASR / TL latency as faint 8pt tags
- `_sanitize_style()` validates the style from user_settings.json (hex colours, clamped numbers) before it is applied
- Original and translation text have independent `font_family` fields (`original_font_family`, `translation_font_family`)
- `SubtitleOverlay.apply_style(style)` updates container/header backgrounds, window opacity, and rebuilds all message HTML
- Style dict stored in `user_settings.json` under `"style"` key; forwarded via `settings_changed` signal → `main.py` → `overlay.apply_style()`
- Backward compat: old `font_family` key auto-migrated to split fields in `apply_style()`

Key overlay features:
- **Top-most**: Toggles `WindowStaysOnTopHint`; requires `setWindowFlags()` + `show()` to take effect
- **Click-through**: Uses Win32 `WS_EX_TRANSPARENT` on the scroll area while keeping header interactive
- **Auto-scroll**: Controls whether new messages/translations auto-scroll to bottom
- **Model combo**: Populated from `user_settings.json` models list; switching emits `model_switch_requested` signal
- **Target Language combo**: Emits `target_language_changed`; synced from settings on startup
- **Compact mode animation**: Toggles between full and minimumHeight with 200ms size animation; uses `frameGeometry()` for actual window size to avoid Windows MINMAXINFO mismatch; skips animation when height difference < 10px
- **Position persistence**: `moveEvent`/`resizeEvent` with 500ms debounce save `overlay_x/y/w/h` to `user_settings.json`; restored on startup
- **Reset positions**: `reset_positions` signal from ControlPanel; subtitle window → (100, 100), overlay → bottom-right of screen

### Settings UX

- **Auto-save with debounce**: All control panel settings (combos, spinboxes) auto-save after 300ms debounce via `_auto_save()` → `_do_auto_save()`. No manual Save button needed.
- **Factory reset** (home page → 維護 → 回復原廠設定, confirm dialog): `factory_defaults.py` is the single source of the install-time values (also used by `launcher/write_settings.py`). `factory_reset()` restores every tunable value, keeps `KEEP_ON_RESET` (model list / connection, ASR model, audio devices, hub) and drops window positions; `ControlPanel.restore_factory_settings()` refreshes the widgets, applies, saves and emits `reset_positions`
- **Slider special handling**: VAD/Energy sliders update labels in real-time but only trigger save on `sliderReleased` (mouse) or immediately for keyboard input (`isSliderDown()` check).
- **Prompt auto-apply**: System prompt TextEdit uses 600ms debounce via `textChanged` signal — no manual Apply button needed.
- **Cache path**: Default `./models/` (not `~/.cache`). Applied at startup in `main.py` before `import torch` via `model_manager.apply_cache_env()`.
- **Whisper group visibility**: Shows/hides download group when switching ASR engine; window auto-resizes via `_fit_height()` (sizeHint clamped to screen).
- **High-DPI fit (issue #39)**: `dialogs.py` provides `available_screen_height()` and `make_scroll_area()` (a content-sized QScrollArea subclass that bypasses QScrollArea's 36x24 font-height sizeHint cap). ControlPanel tabs, ModelEditDialog content, and SubtitleSettingsDialog are wrapped in scroll areas, and window heights are clamped to the screen's availableGeometry so action buttons stay reachable at 150%+ scaling.
- **QDoubleSpinBox precision**: All float values `round()` to 2 decimal places on save to avoid floating-point drift (e.g. `0.9999999999999992`).

### Startup Flow

1. `main.py` reads `user_settings.json` and calls `apply_cache_env()` before `import torch`
2. First launch (no `user_settings.json`) → `SetupWizardDialog`: choose hub + path + download Silero+SenseVoice
3. Non-first launch but models missing → `ModelDownloadDialog`: auto-download missing models
4. All models ready → create main UI (overlay, panel, pipeline)
5. Runtime ASR engine switch: if uncached → `ModelDownloadDialog`; then `_ModelLoadDialog` while the app shuts down the current worker and loads the target worker. If target loading fails, the app tries to restore the previous worker.

### Incremental ASR

Continuous speech is processed incrementally to reduce latency (enabled by `incremental_asr` setting):

- **Pipeline loop** checks `_do_interim_asr()` every ~1s while VAD is accumulating speech (buffer > `interim_interval`)
- **Sentence splitting** via `yasbd-lib` (`pysbd_adapter` keeps the pysbd API; rule-based, 40 languages incl. ko, ~0.2ms/call on subtitle-length text), with comma fallback:
  - the segmenter handles sentence-ending punctuation (。！？!?.) and language-specific rules (Mr./Dr., abbreviations)
  - CJK comma `、` fallback at 25-char threshold (Japanese clause separator)
  - Western comma `,，;；` fallback at 60-char threshold for long unsplit sentences
  - Both fallbacks require `before > 15 chars` and `after > 3 chars` to avoid fragments
- **Trim with safety margin**: After committing sentences, proportional audio trim + 0.3s margin to reduce echo; keeps ≥0.5s remainder
- **Echo dedup**: `_strip_committed_overlap()` removes re-recognized text by matching committed tail against new text prefix
- **Short utterance buffering**: Fragments ≤8 alnum chars buffered in `_interim_pending`, prepended to next sentence

### VAD Behavior

- **Progressive silence**: Buffer越长接受越短的停顿切分 (<3s=full, 3-6s=half, 6-10s=quarter of silence_limit)
- **Adaptive silence**: Tracks recent pause durations, sets threshold to P75 × 1.2, auto-adjusts between 0.3s~2.0s
- **Backtrack split**: Max duration时回溯smoothed confidence history找最低谷切分，remainder保留到下一段
- **Speech density filter**: `_flush_segment()` discards segments where fewer chunks than `min_speech_density` are above the confidence threshold. Setting `vad_min_speech_density` (default 0.25, 0 disables, validated 0-0.9) on the control panel's timing group; lower keeps short replies such as 「え？」
- **Short segment merge**: Segments below `min_speech_duration` are NOT discarded — VAD does a soft-reset (`_is_speaking=False`) but keeps the buffer, which naturally merges with the next speech onset
- **Trimmed segment handling**: `_was_trimmed` flag (set by `trim_front`) ensures interim ASR remainders are `force_flush()`ed instead of being dropped by min_speech check

### Best-combination benchmark (bench/)

Separate tool, never imported by the real-time app: launcher button 最佳組合評測 → `launcher/bench.ps1` (numbered menu) → `launcher/bench_run.py` (`python -I`, `apply_cache_env()` before torch, `__main__` guard for spawn) → `bench/cli.py`.
- Data: `bench/datasets.py` reads the datasets parquet files on the Hub with pyarrow (HfFileSystem range reads, pinned revision): seeded random row groups, PER_GROUP rows each, only those groups downloaded (~550 MB), strictly in plan order, into `bench_clips/<key>/` (16 kHz mono wav + txt + manifest.json; log in `bench_clips/download.log`). Every Hub step runs under a time limit (huggingface_hub 2.x lists files without an HTTP timeout); only network trouble is retried (`NetworkError`, a rerun continues at the same row), `DataError` (missing files, other columns, most rows unusable) and `DiskError` stop at once. Undecodable audio is skipped for that download only (a missing codec looks the same). The datasets-server /rows API was dropped: it returned 5xx for long stretches
- Stages: `bench/orchestrator.py`, results appended to `bench/state.py` jsonl logs. Stage 1 ASR through `ASRClient` with `asr_runner.build_worker_config()` (same keys as main's worker_config) and CER on `displayed_text()` (main's punctuation / noise filters + the shared `asr_language.without_other_language`); stage 2 VAD thresholds with a fresh `VADProcessor` per run (only with `bench_clips/live/`); stage 3 translation alone and together with ASR (real-time replay), then cross judging (`bench/judge.py`, offsets aligned on items scored by at least two judges, aligned scores clamped to 1-10)
- Resume rules (`state.py`): a task marked done / failed is not run again, except failed tasks the user agrees to retry (`cli.cmd_resume`) and judge tasks (always reset). Inside a task that runs again only items that are not final (`state.is_final`) are redone: ASR / translation / judge failures are retried, failures under load (together) are measurements and are kept; the replay writes a category at a time, VAD judging per (ASR, recording, threshold). A resumed run keeps the forced ASR language it started with; stage-1 reuse requires the same clips (`plan["data_ids"]`: method, revision, clip ids) and language. `PLAN_DEFAULTS` fills keys an older plan.json lacks
- Copies of main.py logic are guarded by `tests/test_bench_asr.py` (AST comparison of worker_config keys and Translator kwargs, filter results compared with `LiveTranslateApp`); update both when changing those parts of main.py
- `bench/settings_io.py` applies a recommendation only when LiveTranslate is closed: backup in `bench_results/settings_backups/` (backups taken before a restore are prefixed `pre-restore_` and not offered as "restore"), changes only asr_engine / funasr_model / whisper_model_size / vad_threshold (kept when not measured) / active_model, plus `local_models.remember_selected()`. `recommendations.json` is written by `report.rec_item` and read back through `report.load_recs`, which drops items it cannot apply
- Tests: `LIVETRANSLATE_BENCH_DIR` and `bench.paths.SETTINGS_FILE` are sandboxed in tests/conftest.py, and an autouse guard fails any test that reaches the real Ollama / LM Studio (inject `Deps(ollama_factory=..., manage_ollama=False)`; the `real_llm_servers` fixture gives the real functions to tests of llm_servers itself)

### Key Patterns

- `torch` must be imported before PyQt6 to avoid DLL conflicts on Windows (PyTorch 2.9.0+ bug, see `main.py` and [pytorch#166628](https://github.com/pytorch/pytorch/issues/166628))
- Cache env vars set at module level in `main.py` before `import torch` to ensure `TORCH_HOME` is respected
- Deferred initialization: ASR model loading and settings application happen via `QTimer.singleShot(100)` after UI is shown to prevent startup freeze
- `make_openai_client()` in `translator.py` is the single shared function for proxy-aware OpenAI client creation (used by both translator and benchmark)
- `create_app_icon()` in `main.py` generates the app icon; set globally via `app.setWindowIcon()` so all windows inherit it
- Model cache detection (`is_asr_cached`, `get_local_model_path`) checks both ModelScope and HuggingFace paths to avoid redundant downloads when switching hubs
- Settings log output (`_apply_settings`) filters out `models` and `system_prompt` to avoid leaking API keys
- FunASR Nano: `asr_funasr_nano.py` does `os.chdir(model_dir)` before `AutoModel()` inside the ASR worker process, so relative paths in config.yaml (e.g. `Qwen3-0.6B`) resolve locally instead of triggering HuggingFace Hub network requests, without changing the GUI process cwd
- `Translator` defaults to 10s timeout via `make_openai_client()` to prevent API calls from hanging indefinitely
- Log window is created at startup but hidden; shown via tray menu "Show Log"
- Audio chunk duration is 32ms (512 samples at 16kHz), matching Silero VAD's native window size for minimal latency
- Forced ASR language (`asr_language` != auto): `asr_language.py` (stdlib only, shared by main.py, the Nano worker and bench/) holds the Fun-ASR prompt names, the script check and the filter itself. Fun-ASR-Nano / MLT-Nano take the language as the model card's Simplified-Chinese name inside the prompt (`语音转写成日文：`), not a code; `prompt_language_name()` maps codes (Nano: zh/en/ja only) and Fun-ASR-Nano labels results with the forced language. Labels `auto` / `unknown` / empty (SenseVoice without a tag, remote) count as no label (`engine_label()`). `heard_other_language()` judges a text by the engine label plus its own script (`script_language()`: ja/ko/en only, Latin neutral under ja/ko); `without_other_language()` applies it per sentence. main.py `_accept_language()` (via `_without_other_language()`) filters committed lines (`_process_segment` / `_process_segment_text`), and buffered short fragments (`_interim_pending`), the interim-final remainder and the live preview are judged on their own. `_drop_off_language()` logs `Language filter: ...`, clears that line's live preview, and shows a tray notice after 5 drops in a row, or when 5 of the last 20 lines were dropped (at most every 10 minutes). When the model cannot be told the language (`_note_asr_language_support` → `asr_language.hint_missing`, e.g. Nano + ko) the main log warns and the tray notifies whenever the (engine, model, language) combination changes to one without a hint, and its output is not judged by script. The ASR worker's own log goes to its console only, not to logs/
- `_asr_loop` survives exceptions in segment handling; 3 failures in a row log an error and show a tray notice (`asr_loop_error_msg`)
- FunASR `disable_pbar=True` required in all `generate()` calls — tqdm crashes in GUI process when flushing stderr
- ASR engine lifecycle: the GUI process never instantiates `ASREngine`, `FunASREngine`, or `AnimeWhisperEngine` directly. It owns an `ASRClient`; each worker process owns one concrete backend/model. Engine/model/device changes shut down the current worker first, then start a new worker. On target load failure, the saved previous worker config is used to restore ASR.
- Whisper (ctranslate2) only accepts `device="cuda"` not `"cuda:0"`; device index passed via `device_index` param. Parsed from combo text like `"cuda:0 (RTX 4090)"` in `_switch_asr_engine`
- ASR text density filter: segments ≥2s producing ≤3 alnum characters are discarded as noise
- Settings file uses atomic write (write to `.tmp` then `os.replace`) to prevent corruption on crash
- `stop()` joins pipeline thread before flushing VAD to prevent concurrent `_process_segment` calls
- Cancelled ASR download leaves the current worker running; failed target worker load attempts to restore the previous worker config
- `Translator._build_system_prompt` catches format errors in user prompt templates, falls back to DEFAULT_PROMPT
- Translation prompt presets: `PROMPT_PRESETS` in `translator.py` (daily/esports/anime), selectable via control panel combo
- `translate_iter()` is a generator that yields accumulated partial text for streaming UI; `translate()` is the blocking equivalent
- Streaming UI: `update_streaming_signal` → `ChatMessage.update_streaming()` with 50ms QTimer throttle; `set_translation()` finalizes
- `RepetitionError` raised when model output contains repetition loops (pattern length 8+); caught in `_translate_async`, shows user-facing warning
- Changelog: `i18n/CHANGELOG_{lang}.md` files rendered as HTML in Settings → Changelog tab via `_load_latest_changelog()`
